# ml_pipeline

Trains the interaction-severity model that answers for drug pairs the rule
database does not carry, and exports the on-device copy the app bundles.

## Layout

- `src/features/export_from_bundled_db.py` — rebuilds the training CSVs from
  the shipped `medguard.db`, so a retrain needs no licensed download.
- `src/features/build_features.py` — feature engineering for drug pairs
  (ATC overlap, shared CYP enzymes, NTI flags, per-drug risk priors).
- `src/training/train_model.py` — trains and evaluates the three-tier
  (low / moderate / high) model, writes metrics and the joblib artefact.
- `src/inference/convert_tflite.py` — exports the TFLite model and the metadata
  JSON the app reads.
- `data/external/ddinter/` — the DDInter 2.0 source files. `data/raw/` takes
  the DrugBank export (not included; see below). `data/processed/` and
  `data/interim/` are regenerated by the commands below. `data/samples/` holds
  small API response fixtures.
- `models/bundled_db/` — **the model the backend serves**, complete with its
  binary and every metadata file it loads.
- `models/` (top level) — metrics and metadata of the original model the
  dissertation reports. Its binary was not retained.

Install `pandas numpy joblib pyarrow` and the scikit-learn release pinned in
`backend/requirements.txt` — the backend has to load whatever you train, and a
pickled model only loads reliably under the version that saved it.

## Retraining without any download (what runs today)

```bash
python -m ml_pipeline.src.features.export_from_bundled_db
python -m ml_pipeline.src.features.build_features random
MEDGUARD_MODELS_OUT=ml_pipeline/models/bundled_db \
  python -m ml_pipeline.src.training.train_model random
```

`MEDGUARD_MODELS_OUT` keeps the run out of `models/`, so the metrics the
dissertation cites are never overwritten. Copy `feature_columns.json` and
`drug_risk_lookup.json` (from `data/interim/retrain/random/`) plus
`enzyme_index.json`, `pd_class_meta.json` and `nti_list.json` (from
`data/interim/retrain/`) next to the model — the backend loads all of them from
the model's own directory.

**Read `models/bundled_db/PROVENANCE.md` before quoting any of its numbers.**
That model is trained on the shipped database, whose label mix is nothing like
the original corpus, and its high-tier precision is much worse.

## Reproducing the original model (needs the DrugBank export)

The first model learned from ~1.45M pairs built from the full DrugBank export,
a ~1.5 GB file that is not in this repository. Reproducing it means fetching it
again:

1. Sign in at <https://go.drugbank.com> with an account approved for academic
   access. As of September 2026 DrugBank has paused new academic downloads.
2. **Downloads → Latest Release → Complete Database** — the full database XML,
   released under CC BY-NC 4.0.
3. Unzip and place the XML at
   `ml_pipeline/data/raw/drugbank_all_full_database.xml`.
4. The DDInter 2.0 CSVs are already in `ml_pipeline/data/external/ddinter/`. If
   they ever go missing, re-download the eight ATC-grouped files (A, B, D, H,
   L, P, R, V) from <https://ddinter2.scbdd.com/download/>.
5. Rebuild the database and then the model:

   ```bash
   python -m data_pipeline.refresh_db
   python mobile/tool/optimise_db.py mobile/assets/db/medguard.db
   python -m ml_pipeline.src.features.build_features random
   python -m ml_pipeline.src.training.train_model random
   ```

The DrugBank XML stays out of the repository (`data/raw/` is ignored), as do
the processed and interim datasets, which the commands above regenerate.

## What is in the repository

- `models/bundled_db/` in full, binary included, so the backend serves
  predictions on a fresh clone with no training step.
- The original model's metrics and metadata at `models/` — the numbers the
  dissertation cites.
- The on-device model the app ships, at `mobile/assets/ml/`. The pipeline's own
  export (`models/severity_mlp.tflite`) is an identical copy and is not
  tracked.

Binaries a retrain writes to the top of `models/` stay untracked until you
deliberately move them into place.

## Severity labelling

The model predicts a three-tier risk level. Its *labels* come mostly from a
clinical-effect heuristic, with DDInter 2.0 expert grades over a minority of
pairs — which is why the training corpus skews moderate. That skew is a
property of the labels, not a defect of the model, and the tier the user sees is
always the more cautious of the rule database and the prediction.
